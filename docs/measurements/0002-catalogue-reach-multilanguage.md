# Measurement 0002: Catalogue reach on Go, JavaScript and Java

**Status:** Complete
**Date:** 2026-08-11
**Instrument:** [`scripts/measure-catalogue-reach.py`](../../scripts/measure-catalogue-reach.py)
**Tracker:** `INV-linub` (the class), `INV-suril` (java statics), `INV-gijis` (JS)

## The question

INV-linub's statement verbatim: *a catalogued I/O call site must reach its
catalogue entry regardless of receiver syntax.* The instrument generates one
call site per catalogue entry and asks production whether a boundary comes back
attributed to the calling function. It had only ever been run on Python.

## Headline

| language | catalogued | attributed | unattributed | forms probed |
|---|---:|---:|---:|---|
| python | 215 | 210 (97.7%) | 5 | dotted, bare |
| javascript | 187 | 182 (97.3%) | 5 | dotted, bare |
| java | 142 | 129 (90.8%) | 13 | instance, static |
| go | 210 | 162 (77.1%) | 48 | dotted |

Per-form detail:

| language | both forms | dotted / instance only | bare / static only | neither |
|---|---:|---:|---:|---:|
| python | 194 (90.2%) | 16 | 0 | 5 |
| javascript | 135 (72.2%) | 47 | 0 | 5 |
| java | 0 | **0** | 129 (90.8%) | 13 |
| go | — (single form) | 162 (77.1%) | — | 48 |

## The probe was excluding its own fixture, and the first Go run reported 0%

The first Go run returned **0 of 210 attributed** and the instrument's own
positive control refused to publish it: *"NOTHING RESOLVED. This is a broken
fixture or a broken pipeline, not a catalogue gap. Refusing to report a 100%
miss."* That refusal is the only reason the number did not ship.

The cause was the probe's own header. `supply_chain.is_likely_minified`
heuristic 3 matches `/(Generated by|@generated|DO NOT EDIT)/i` anywhere in a
file's first five lines and classifies the file `Tier.DERIVED`. The fixture's
banner read `// generated by scripts/measure-catalogue-reach.py`.

Controlled, identical body, only the header differing:

| header | Go boundaries |
|---|---:|
| *(none)* | 2 |
| `// leading comment` | 2 |
| `// generated by scripts/measure-catalogue-reach.py` | **0** |

Bisected to the exact phrase: `// generated` scores 2, `// generated by` scores
0. **Python is not affected by the same classification** — a `probe.py` with and
without the identical banner both return 3 boundaries — so the previously
published Python numbers stand, and the per-language asymmetry is a finding in
its own right (filed).

There are also **two different generated-file predicates in one module**:
`_GENERATED_HEADER_PATTERN` (strict — requires `@generated`, or `Code generated
by … DO NOT EDIT`, at a comment-prefixed line start) and `is_likely_minified`
heuristic 3 (loose — any `Generated by` / `DO NOT EDIT` anywhere in the first
five lines, case-insensitive, no comment prefix). They disagree about this very
file.

## Per-language findings

### Go — every method-kind entry is unattributed

162 of 210 attributed. The 48 misses are **45 method-kind entries and 3
attributes**, i.e. *100% of Go's method-kind catalogue surface* is
unattributed, while function-kind entries attribute at 100%. Concentrated in
`net_send` (25), `net_recv` (9), `logging` (5) and `subprocess` (4).

This is the same shape Python showed before its receiver-typing work — that
run had 78 of 83 misses method-kind — which makes Go the natural next target
for the same fix rather than a new problem.

The 3 attribute-kind misses (`os.Stdin`, `os.Stdout`, `os.Stderr`) *do* produce
a chain; it is anchored to a file node rather than to the calling function, so
they are an attribution defect and not a reach gap. The instrument reports that
bucket separately for exactly this reason.

### JavaScript — the fixture shape dominated the answer, by 35×

Two runs, same catalogue, same call sites, differing only in **where the
`require` sits**:

| `dotted` form | attributed by that form |
|---|---:|
| `function f() { const m = require('fs'); return m.readFile(a, b); }` | 4 of 187 (2.1%) |
| `const m = require('fs');` at module scope, `m.readFile(a, b)` inside | 182 of 187 (97.3%) |

The module-scope form is the dominant JS idiom and is what the final numbers
use. But the function-local form is real code too — lazy `require` inside a
function is a common pattern for optional dependencies and startup cost — and
it is **97.9% blind**. That is a recall gap with a clear shape, and it is not
what INV-gijis describes.

Only 5 entries are unattributed by either form (4 method-kind, 1 function).

### Java — the static form attributes, the instance form never does

129 of 142 attributed, **every one of them via the STATIC form**
(`Files.write(a, b)`), and **zero** via the instance form (`new
File(a).exists(b)`). The 13 misses are all `db_read` (8) and `db_write` (5).

The instance-form zero is a clean extreme and is reported as an observation,
not a conclusion: the fixture demonstrably parses and resolves, since the static
form scores 90.8% on the same file, so the analyzer is not blind to it — but
chained construction (`new T(a).m(b)`) attributes nothing, and why was not
diagnosed here.

**This does not reproduce INV-suril.** That item states the entire
`java.nio.file.Files` sink surface "can never match" because the entries are
catalogued `kind=method` while the analyzer emits static calls with no
`call_construct`. In this probe the `Files` entries attribute normally — but
here the import supplies a module hint, so the no-module-hint gate the item
names is never reached. The item's own repro (sherpa-onnx) needs re-running
against this result before either is trusted; the probe answers a neighbouring
question, not the same one.

### Python — re-measured, and it has improved since it was last recorded

`DOTTED+BARE 194 / DOTTED 16 / BARE 0 / NEITHER 5` against the recorded
`BOTH 153 / DOTTED 16 / BARE 41 / NEITHER 5`. 41 primitives moved from
bare-only to both, so the dotted (module-qualified) path gained ground; the
denominator, the dotted-only set and the residual are unchanged.

## What this does not support

- **Attribution, not reachability.** The verdict asks whether production named
  the *calling function* as the chain's `io_edge_src`. A primitive can produce a
  chain and still score unattributed; those are counted separately.
- **A lower bound in the idiomatic direction only.** A primitive that attributes
  here can still be missed through an alias, a re-export, a conditional import
  or a wrapped receiver.
- **Not a recall estimate on real code.** The precedent is on the record: the
  change that motivated the Python run moved 78 primitives on this probe and
  **zero edges** on two real repositories.
- **Form vocabularies are not comparable across languages.** Go has one
  idiomatic form and Java's pair is instance/static, not dotted/bare. Reading
  Go's 77.1% against Python's 97.7% as "Go is worse" ignores that they are
  scored over different form counts.
